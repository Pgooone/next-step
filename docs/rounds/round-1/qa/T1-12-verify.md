## 三、三个实现裁量裁决

### 裁量① 零框架原生 JS（卡文字写 React）——**裁决：合规，登记卡文字勘误**

- 卡 L3 行「React，不引组件库」与实现（零 react 依赖、esbuild 直打包）字面冲突；但卡的硬约束链是「不引组件库（N 清单红线）+ presentation 纯数据 + 通用渲染器 + 零领域判断」——实现全部满足且更彻底（零框架运行时）。渲染器输出纯数据树（RenderNode），换任何渲染技术只动 `dom.ts` 一个挂载层，D8「两壳零改动」实证反而更强。卡内「vitest + testing-library 等价」以纯函数树断言直接满足「等价」。
- 处置：**采纳实现，登记卡文字勘误**——L3 行「React」应勘为「零框架原生 JS（渲染技术不绑定）」。

### 裁量② 新增第 11 端点 GET /api/audit/replay ——**裁决：合规采纳，建议详设 §6 接口表补登记**

- **必要性**：P1-4 要求回滚报告「确认过 N 块」从审计回放取数而非版本 diff 重算；面板是浏览器不能读文件，必须有 HTTP 读面。最小增量（一个 GET）。
- **壳零判断**：handler = `readAll()` + `artifactId` 数据过滤（序列化层职责），无领域决策、无 if 分支（`create-server.ts:259-272` 代码审查成立）。
- **只读**：零写操作；web-panel.jsonl 唯一 writer 仍是 server 进程（单 writer 锁不因此端点弱化）。
- **权限面**：路径固定（构造注入，无用户可控路径 → 无穿越）；响应只含审计 data 字段（自家 schema）；实测带/不带 artifactId 过滤行为正确（单测另覆盖）。
- **取数正确性**（行为验证）：三组不同 fixture（3 收 2 拒 / 4 收 1 拒 / 5 收 0 拒）回滚报告分别显示「确认过的 3/4/5 块」——**非硬编码、非巧合相等**，卡断言 3 的判别性要求满足。

### 裁量③ 回滚灰化块（同会话缓存 / 刷新降级）——**裁决：方向可接受，登记口径不准，升级为 P1-b（见 findings）**

- 实测三形态：**窄路径**（写回后不刷新同会话回滚）：5 块灰化 + 「未生效（v4 提案）」标注 + 审计数值全对（S3b 四条断言）；**PRD S3 标准流**（面板打开即无 pending → 回滚，即 PRD 前置「文档已有 v1–v4 版本链」的常态）：灰化块 **0**；**刷新后**：灰化块与回滚报告横幅**均**丢失（`rolledback` 是纯内存态），只剩正文=当前版内容、面板可用不白屏。
- S3④ 底线核查：正文切换为 v2 时代内容 ✓（全部序列）、被删段落恢复显示 ✓、新增节隐藏 ✓、横幅报告+动作 ✓（同会话）——底线成立；但「v4 提案块灰化标未生效」在 PRD 自己定义的标准前置下不可达。
- 登记口径偏差：裁量写「刷新后仅横幅+正文」，实测刷新后横幅也丢；且降级面不止刷新——标准流打开即无灰化块。根因真实（审计条目无块行内容，跨会话无法重建提案块，第一期 MVP 边界），但应按「PRD 偏差 + 第三期审计 schema 捞回」正式登记，而非含混为实现裁量。

## 五、Findings（分级）

| 级 | 项 | 明细 |
| --- | --- | --- |
| **P1-a** | 撤销回滚横幅文案与确认计数错 | 显示「v6 = **v5** 内容（含你确认的 **0** 块）」，实际 v6=v4 内容、4 块（fetch 逐字节证实）。根因：`panel.ts` undoing 场景消费 `resp.fromVersion`（=操作前当前版 v5）而应消费 `resp.toVersion`（=恢复目标 v4），横幅文案（`panel.ts:313`）与 `afterRollback` 的 confirmedCount 取数键（`panel.ts:616`）两处同根。L1 响应语义自洽（fromVersion=操作前版，两种回滚一致），bug 纯在面板消费侧。数据层零错误，不破卡断言字面（卡断言 3 只要求回滚报告数值正确——首次回滚报告实测正确）。 |
| **P1-b** | PRD S3 标准流灰化块缺失 + 裁量③登记口径偏差 | 见裁决③。灰化块仅「写回后同会话回滚」窄路径可达；PRD S3 前置（v1–v4 已物化）的标准流恒为降级形态；刷新后横幅亦丢（超出「仅横幅+正文」口径）。处置：正式登记 PRD 偏差 + 第三期审计条目补块行内容后捞回；正文切换/报告数值/append-only 底线全部成立，不阻塞。 |
| **P2-a** | 回滚后版本链抽屉不自动关闭 | `openHistory` 挂在 body，回滚后 `render()` 不清它——回滚报告横幅被抽屉遮挡，「撤销回滚」按钮点击被拦截（实测 CDP 拦截日志），用户须手动关抽屉。S3④ 反馈可达性受损一步。 |
| **P2-b** | S4 警告横幅物化文件名不实 | `panel.ts:282` 硬编码 `${a.title}.md`；实际物化是避让后缀文件（实测 `-15.md`）。ArtifactDetail 未暴露 filePath，面板只能猜。用户按提示去磁盘找文件会找到同名旧残留（seed 多跑后同目录一堆 `-N.md`），有实际误导。建议 server 详情端点补 filePath 字段。 |
| **P3-a** | undo 产物版本再回滚时 confirmedCount=0 | 撤销回滚生成的版本（如 v6）无 artifact_resolved 条目，对它再回滚时取数键落空 → 显示「确认过的 0 块」。与 P1-a 同根，冷门路径。 |
| **P3-b** | seed 残留旧物化 .md | `seed-demo.mjs` 幂等重建只删 `nextstep/` 子目录，项目根物化 .md 残留（本轮验收后堆积至 `-15`）。seed 注释自知但未处理；同内容多文件曾误导 verifier 首轮手改定位（脚本侧已改按 artifact.json.filePath 权威定位规避）。 |
