## round-1 范围（正本 §10 第一期）

**CLI 侧**：L1 原样搬（artifact-service / pending-change-service / lcs）→ L2 注册提议三工具 + 只读三工具 → doc 工具集物理禁用 write/edit → CliDecisionPort（ctx.ui）→ sourceRef 随工具写入 appendEntry（M2a，只写不查）→ 单 Agent 会话跑通「建文档 → 提议改 → 逐块确认 → 物化留版 → 版本/回滚」。

**Web 轨（D8）**：受管文档面板全套——块级绿/红/黄高亮、确认分档交互（整块收/逐块/混合，写回 approval_response，**作用于存储态 PendingChange——EntryDecisionPort 跨端实时唤醒冻结至第四期**）、版本链、回滚（方案 C：正文切换 + 回滚报告 + 撤销回滚）、外部手改检测提示（三动作：查看 diff / 以提案合并 / 拒绝采纳）。**呈现以「文档内联沉浸审阅」为目标方案（D6），保底退「单卡逐块列表」。**薄 server 直调 L1 领域服务，组件零领域判断。

**出口判据**：AC-1.1~1.4 全绿；F1 在纯 CLI 端到端成立；EXTERNAL_MODIFIED 保护实测有效；presentation 纯数据 + 通用渲染器承重实证通过。

**不做**：多 Agent、编排、归因查询（trace_defect 属第三期）。

## 场景剧本（走查/验收两用）

> 用户角色：单人产品所有者（非技术向为主，操作要「说人话」）。面板 = 自建薄 Web 壳的受管文档面板。

### S1 · 主路径：逐块混合确认（对应 F1 / D6 确认分档）

- **前置**：doc 模式 Agent 已对「设计文档.md」发起 v3→v4 提案，共 5 块改动（1 修改 / 1 新增 / 1 删除 / 2 修改）。
- **步骤**：
  1. 打开面板，看到文档以「文档内联」方式呈现：未改动段落正常显示，5 个改动块以高亮卡片嵌在原位，块内绿 +红 −。
  2. 逐块点 ✓/✗：块 1 ✓、块 2 ✓、块 3 ✗、块 4 ✓、块 5 ✗——每块状态即时变色（绿/红/黄），进度指示实时更新。
  3. 全部块有着落（无待定）后，「写回」按钮激活。
  4. 点「写回」→ 系统写回 approval_response（含逐块明细）→ 接受的块物化为 v4，被拒的块保留 v3 内容。
- **期望（可断言）**：①5 块状态三色可见且与点击一致；②存在待定块时写回不可用；③写回后版本链出现 v4，且 v4 内容 = v3 + 被接受的块；④被拒块不进 v4；⑤每次裁决落入 append-only 日志。

### S2 · 批量档：全部接受（对应 D6 交互可分档）

- **步骤**：打开面板 → 点「✅ 全部接受」→ 5 块全部变绿、进度 5/5 → 写回激活 → 写回。
- **期望**：一键后无待定块；写回后 v4 = 提案全部内容。单块按钮在批量后仍可翻转（混合档：先全收再打回单块）。

### S3 · 版本链与回滚（对应 M1 版本链/回滚）

- **前置**：文档已有 v1–v4 版本链。
- **步骤**：点「版本链」→ 抽屉列出 v1–v4（每版：版本号、归属 stage/agent、时间、变更摘要）→ 对 v2 点「回滚到此版」→ 确认提示 → 执行。
- **期望**：①版本链完整可见且归属正确；②回滚 = 以 v2 内容生成**新版本 v5**（不是删除 v3/v4，历史 append-only）；③回滚后当前版本显示 v5，v3/v4 仍可在链上查看；④**回滚反馈（方案 C）**——正文切换为 v2 时代内容（v4 提案块灰化标「未生效」、新增段隐藏、被删的 §4 段落恢复显示），顶部横幅给出回滚报告（撤销 5 块、其中确认过 N 块、appendEntry 注记）与「查看差异」「撤销回滚」动作；⑤**撤销回滚**——点击后以 v4 内容生成新版本（版本号递增），正文恢复 v4 形态（提案块恢复、§4 消失），回滚版保留在版本链上。

### S4 · 异常路径：外部手改检测（对应 EXTERNAL_MODIFIED / AC 通行）

- **前置**：用户绕过系统用编辑器直接改了受管文档的物化文件。
- **步骤**：打开面板（或下次提交时）。
- **期望**：①顶部出现显式警告横幅（EXTERNAL_MODIFIED），说明检测到外部手改；②提供「查看 diff」与处理动作（拒绝采纳/以提案方式合并），**不得静默覆盖或静默丢弃**；③警告消除前版本操作（写回/回滚）被阻止或需先处理手改。

### S5 · CLI 侧主路径（对应 F1 纯 CLI 成立，真机验收）

- **步骤**：终端单 Agent 会话：create_artifact 建文档 → propose_edit 提议 → CLI 汇总卡（A 方案）呈现 5 块 → 快捷键逐块/全收 → 物化留版。
- **期望**：①doc 模式工具集物理无 write/edit（AC-1.3）；②三个只读工具返回结构化结果（AC-1.1/1.4）；③确认后版本链与 Web 面板看到的同一份（唯一真相 JSONL）；④受管路径直写被硬挡（D10）。

多 Agent 编排、Recipe 迁移、trace_defect 归因、DAG/并行、自动沉淀、部署/CI、多用户。
